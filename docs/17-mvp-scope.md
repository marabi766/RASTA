## ۱۷٫۳ P2 — سخت‌سازی روز ۳۰

| مورد                      | Acceptance Criteria                                                  |
| ------------------------- | -------------------------------------------------------------------- |
| **Freeze نسبی Feature**   | فقط رفع باگ و بدهی معماری                                            |
| تکمیل پوشش تست تا آستانه  | `economic` و `identity` ≥ ۹۰٪؛ بقیه ≥ ۷۵٪                            |
| تست بار (k6)              | همه سناریوهای § ۱۴٫۸ در آستانه                                       |
| بهینه‌سازی Query          | حذف N+1؛ هر Query کند > ۵۰۰ms بررسی و Index شده                      |
| اسکن امنیتی کامل          | SAST، DAST، Container، Dependency، Secret — بدون یافته Critical/High |
| Threat Model نهایی        | همه دامنه‌ها با Mitigation قابل ردیابی به کد یا تست                  |
| Helm Chart کامل           | استقرار روی Staging با یک فرمان                                      |
| NetworkPolicy             | Deny پیش‌فرض؛ فهرست سفید صریح                                        |
| Backup و **تست Restore**  | Restore واقعی اجرا و **توازن دفتر کل پس از آن اثبات شود**            |
| Runbookها                 | برای **هر هشدار** یک Runbook                                         |
| مشاهده‌پذیری کامل         | داشبورد Grafana، هشدارها، انتشار Trace انتها به انتها                |
| **تست Developer Handoff** | **یک توسعه‌دهنده جدید در ≤ ۱ روز به Feature اول برسد**               |
| ۲۴ سند به‌روز             | هیچ سندی با کد ناهمگام نباشد                                         |
| ADRها کامل                | هر تصمیم مهم ثبت‌شده                                                 |
| رفع بدهی معماری           | فهرست شناسایی و اولویت‌بندی‌شده؛ موارد بحرانی رفع‌شده                |
