## ۲۰٫۳ Checklist سخت‌سازی امنیتی

### هر Endpoint

- [ ] احراز هویت الزامی (یا `@Public()` صریح و مستند)
- [ ] بررسی نقش
- [ ] **بررسی مجوزدهی سطح Object (BOLA)**
- [ ] ورودی با Zod `.strict()` اعتبارسنجی می‌شود
- [ ] Rate Limit اعمال می‌شود
- [ ] عمل تغییردهنده وضعیت `AuditEvent` تولید می‌کند
- [ ] عمل مالی `Idempotency-Key` می‌گیرد
- [ ] پاسخ خطا داده حساس فاش نمی‌کند
- [ ] `404` برای منبع مستأجر دیگر (نه `403`)

### زیرساخت

- [ ] Container با کاربر غیر ریشه · `readOnlyRootFilesystem` · Capability حذف‌شده
- [ ] NetworkPolicy با Deny پیش‌فرض
- [ ] Secret از Store خارجی، نه ConfigMap
- [ ] TLS در همه مرزهای بیرونی
- [ ] هیچ Secret در Image یا Repository

### داده

- [ ] داده حساس در حالت سکون رمزنگاری‌شده
- [ ] **پیشنهاد مناقصه تا مهلت رمزنگاری‌شده و غیرقابل مشاهده برای اپراتور**
- [ ] Redaction Log فعال و تست‌شده
- [ ] Backup رمزنگاری‌شده
- [ ] **Trigger تغییرناپذیری دفتر کل فعال و تست‌شده**

## ۲۰٫۴ Checklist پایایی

| کنترل                  | جای اعمال                                | تأیید                                    |
| ---------------------- | ---------------------------------------- | ---------------------------------------- |
| Timeout                | هر فراخوانی داخلی و هر Activity          | بازبینی کد + تست                         |
| Retry با Backoff       | خطاهای گذرا                              | تست یکپارچگی با شکست تزریق‌شده           |
| Circuit Breaker        | هر کلاینت REST داخلی                     | تست: افت Downstream → پاسخ سریع، نه معلق |
| Idempotency            | هر Endpoint مالی و هر Consumer           | تست بازپخش                               |
| Outbox                 | هر سرویس منتشرکننده                      | **آزمایش آشوب: قطع Kafka → بدون گم شدن** |
| DLQ                    | هر Consumer                              | تست: پیام بد → DLQ + هشدار               |
| جبران Saga             | هر Saga                                  | تست: شکست هر مرحله → جبران درست          |
| Bulkhead               | صف‌های Temporal                          | تست: صف کند، صف دیگر را نمی‌خواباند      |
| Graceful Shutdown      | هر سرویس                                 | تست: SIGTERM → اتمام درخواست‌های جاری    |

**آزمایش آشوب (روز ۲۶) — سناریوهای الزامی:**

```
۱. Kafka خاموش شود حین ثبت سفارش
   → انتظار: سفارش ثبت می‌شود، رویداد در outbox می‌ماند، پس از بازگشت منتشر می‌شود
۲. یک سرویس Downstream خاموش شود
   → انتظار: Circuit Breaker باز، پاسخ سریع UPSTREAM_UNAVAILABLE، بدون آبشار
۳. Redis خاموش شود
   → انتظار: Cache Miss، سیستم کندتر اما کار می‌کند؛ عملیات نیازمند قفل رد می‌شوند نه اشتباه اجرا
۴. سرویس حین Workflow مناقصه Restart شود
   → انتظار: مهلت‌ها حفظ می‌شوند، Workflow ادامه می‌یابد
۵. پایگاه داده حین تسویه قطع شود
   → انتظار: تراکنش Rollback، وجه در Hold می‌ماند، هیچ Journal ناقصی نیست
```

## ۲۰٫۵ تست Developer Handoff (روز ۳۰)

**سناریو:** یک توسعه‌دهنده که هیچ‌وقت این پروژه را ندیده، Repository را Clone می‌کند.
تنها منبع او `README.md` و `docs/` است.

| # | وظیفه                                       | زمان هدف | معیار موفقیت                                  |
| - | ------------------------------------------- | -------- | --------------------------------------------- |
| ۱ | Clone و نصب وابستگی‌ها                      | ۱۰ دقیقه | `pnpm install` بدون خطا                       |
| ۲ | بالا آوردن محیط                             | ۲۰ دقیقه | `pnpm infra:up` → همه Container سالم          |
| ۳ | اجرای Migration و Seed                      | ۱۰ دقیقه | داده نمایشی در پایگاه داده                    |
| ۴ | اجرای همه سرویس‌ها                          | ۱۰ دقیقه | `pnpm dev` → همه `/health/ready` سبز          |
| ۵ | ورود به UI و مرور Demo                      | ۱۰ دقیقه | هر دو سناریو در مرورگر کار می‌کنند            |
| ۶ | اجرای تست‌ها                                | ۳۰ دقیقه | `pnpm test` سبز                               |
| ۷ | فهمیدن معماری                               | ۱ ساعت   | می‌تواند توضیح دهد چرا Wallet ≠ Ledger        |
| ۸ | **افزودن یک فیلد به یک موجودیت**            | ۱ ساعت   | Migration، DTO، تست، OpenAPI — همه به‌روز     |
| ۹ | **افزودن یک Endpoint ساده**                 | ۲ ساعت   | با Guard، تست جداسازی، مستند                  |
| ۱۰| **ساخت یک سرویس جدید از Checklist**         | ۲ ساعت   | § ۱۵٫۸ کافی و کامل است                        |

**اگر این تست شکست بخورد، Developer Handoff ناقص است** و مستندسازی باید اصلاح شود —
نه اینکه شکست نادیده گرفته شود.

## ۲۰٫۷ آنچه در روز ۳۰ **ادعا نمی‌شود**

```
❌ «سیستم Production ملی است»          → یک MVP مهندسی‌شده است
❌ «اتصال بانکی برقرار است»            → MockPaymentProvider است
❌ «کاملاً امن است»                    → کنترل‌های مشخص دارد؛ امنیت مطلق وجود ندارد
❌ «آماده بهره‌برداری در ۳۲۸ دهیاری»   → آماده استقرار آزمایشی است
❌ «X درصد صرفه‌جویی ایجاد می‌کند»     → مشروط به خط مبنای سال نخست
❌ «همه Featureهای سند محصول کامل است» → فازبندی صریح در MVP Scope
```

**آنچه ادعا می‌شود:** یک معماری Microservices واقعی، با پایگاه داده واقعی، API واقعی،
Event Bus واقعی، احراز هویت واقعی، گردش‌کار واقعی، دفتر کل دوطرفه واقعی، تست، امنیت پایه
جدی، استقرار تکرارپذیر و مستندات کافی برای تحویل به تیم انسانی.
