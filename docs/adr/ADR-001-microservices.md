# ADR-001: معماری Microservices

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26
- **تصمیم‌گیرنده:** Principal Architect

## Context

رستا باید از ۳۲۸ دهیاری استان یزد به شهرداری‌ها، مقیاس ملی و در نهایت یک Marketplace عمومی
برسد — بدون بازطراحی بنیادین Core Platform. دامنه شامل هفت حوزه با مرزهای روشن است: هویت،
دارایی و ناوگان، نگهداری، بازار و تأمین، عملیات عمرانی، موتور اقتصادی، و پشتیبانی.

بار محاسباتی فاز اول کوچک است (ده‌ها تراکنش در روز). مسئله اصلی **مقیاس محاسباتی نیست**؛
مرزبندی داده و امکان رشد تدریجی تیم است.

## Decision

سیستم از روز اول به **۱۶ Microservice دامنه + یک API Gateway** تقسیم می‌شود. هر سرویس
مالک انحصاری پایگاه داده خودش است و فقط از راه REST یا رویداد Kafka ارتباط می‌گیرد.

سه تجمیع آگاهانه برای پرهیز از Over-Engineering انجام شده (economic، asset+insurance،
inventory+logistics) — هر سه با مرزبندی داخلی کامل و مسیر استخراج مستند.

## Alternatives Considered

| گزینه | مزیت | عیب | چرا رد شد |
| --- | --- | --- | --- |
| Modular Monolith با تقسیم بعدی | ساده‌تر، سریع‌تر، عملیات سبک‌تر | مرز داده‌ای عملاً رعایت نمی‌شود | یک JOIN بی‌ضرر امروز، وابستگی غیرقابل جدا کردن فرداست. هزینه اصلاح بعدی بیش از هزینه اولیه است. |
| ۲۲ سرویس مطابق فهرست اولیه دامنه‌ها | مرزبندی حداکثری | Over-Engineering؛ Saga مالی غیرضروری | سرویس‌هایی با مرز تراکنشی مشترک نباید جدا شوند |
| Serverless / FaaS | مقیاس خودکار | مدل تراکنشی برای دفتر کل نامناسب؛ Cold Start | یکپارچگی مالی نیازمند تراکنش پایدار است |

## Consequences

**مثبت**

- مالکیت داده تحمیل‌شده؛ نشت مرز در زمان Build دیده می‌شود
- استقرار و مقیاس مستقل هر سرویس
- گذار به مقیاس ملی یک تصمیم استقرار است، نه بازنویسی
- امکان کار موازی تیم‌های مستقل

**منفی**

- پیچیدگی عملیاتی بالاتر: ۱۷ Deployment، ۱۶ پایگاه داده، Event Bus، Workflow Engine
- اشکال‌زدایی توزیع‌شده دشوارتر است
- سازگاری نهایی به‌جای فوری در مرزهای سرویس
- منحنی یادگیری بالاتر برای تیم انسانی
- زمان توسعه اولیه بیشتر از Monolith

**خنثی**

- نیازمند Trace انتها به انتها از روز اول (که مستقل از این تصمیم هم مطلوب بود)

## Compliance

- قاعده ESLint `no-restricted-imports` هر import از `services/*/src/**` را خطا می‌کند
- هر سرویس نقش پایگاه داده اختصاصی دارد؛ دسترسی متقابل در سطح PostgreSQL ممنوع است
- تست Tenant Isolation به‌ازای هر سرویس
- بازبینی معماری برای هر سرویس جدید: «آیا استقلال فیزیکی ارزش دارد؟»
