# ADR-005: مالکیت پایگاه داده به‌ازای هر سرویس

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26
- **اهمیت:** قاعده بنیادین — نقض آن رد شدن تغییر است

## Context

رایج‌ترین شکست معماری Microservices این است: سرویس‌ها جدا می‌شوند اما همچنان به یک پایگاه
داده مشترک وصل‌اند. نتیجه، «Distributed Monolith» است — همه هزینه‌های توزیع‌شدگی، بدون
هیچ‌کدام از مزایای آن. یک تغییر Schema همه سرویس‌ها را می‌شکند و استقرار مستقل ناممکن می‌شود.

## Decision

**هر سرویس مالک انحصاری پایگاه داده خودش است.**

- هیچ سرویسی جدول سرویس دیگر را نمی‌خواند یا نمی‌نویسد
- هیچ جدول مشترکی وجود ندارد
- هیچ Join میان‌سرویسی وجود ندارد
- ارتباط فقط از راه REST یا رویداد Kafka

**MVP:** ۱۶ پایگاه داده منطقی روی یک Cluster PostgreSQL، هر کدام با **نقش و اعتبارنامه
اختصاصی** و `REVOKE ALL ... FROM PUBLIC`.

**Production:** تفکیک به چند Cluster بر مبنای پروفایل بار؛ `economic` و `audit` روی
Cluster اختصاصی.

## Alternatives Considered

| گزینه | مزیت | عیب | چرا رد شد |
| --- | --- | --- | --- |
| پایگاه داده مشترک با Schema جدا | Join ممکن؛ تراکنش سراسری | مرز فقط قراردادی است و به‌مرور شکسته می‌شود | مرز باید تحمیل‌شدنی باشد، نه توافقی |
| پایگاه داده مشترک با یک کاربر | ساده‌ترین | هیچ مرزی وجود ندارد | Distributed Monolith |
| جداسازی فیزیکی از روز اول | مرز حداکثری | هزینه زیرساخت و عملیات بالا در MVP | جداسازی منطقی همان تضمین را در این مقیاس می‌دهد |

## Consequences

**مثبت**

- تغییر Schema داخلی یک سرویس، هیچ سرویس دیگری را نمی‌شکند
- استقرار مستقل واقعاً ممکن است
- گذار به Cluster جدا فقط تغییر Connection String است
- مرز در سطح PostgreSQL تحمیل می‌شود، نه صرفاً در سطح کد

**منفی**

- داده مرجع باید تکرار شود (Replica محلی از رویداد)
- گزارش‌های میان‌دامنه‌ای نیازمند `analytics-service` هستند، نه یک Join ساده
- سازگاری نهایی به‌جای فوری در مرزها
- تراکنش سراسری وجود ندارد — نیاز به Saga

**خنثی**

- در MVP همه روی یک Cluster اجرا می‌شوند؛ نقطه شکست واحد ثبت‌شده در Risks S-01

## Compliance

- اسکریپت `00-init-databases.sh` نقش و پایگاه داده مجزا می‌سازد و دسترسی PUBLIC را لغو می‌کند
- قاعده ESLint، import میان‌سرویسی را خطا می‌کند
- بازبینی کد: هر `$queryRaw` بررسی می‌شود که فقط جداول خود سرویس را لمس کند
- تست یکپارچگی: هر سرویس فقط با اعتبارنامه خودش به پایگاه داده خودش وصل می‌شود
