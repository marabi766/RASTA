# ADR-007: Redis برای Cache، قفل توزیع‌شده و Rate Limiting

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26

## Context

سه نیاز مجزا وجود دارد که همگی به یک ذخیره‌ساز سریع و مشترک نیاز دارند:

1. **Cache** — مجوزهای مؤثر کاربر، فراداده سازمان و JWKS در هر درخواست خوانده می‌شوند.
2. **قفل توزیع‌شده** — رزرو موجودی انبار و عملیات چندکیف‌پولی نیازمند هماهنگی میان
   نمونه‌های موازی یک سرویس‌اند.
3. **Rate Limiting** — شمارنده باید میان همه نمونه‌های Gateway مشترک باشد.

## Decision

**Redis 7.4** با `maxmemory-policy = noeviction`.

کاربردها: Cache · Rate Limit (Sliding Window) · قفل توزیع‌شده · سبد خرید · Cache پاسخ
Idempotency در لایه Gateway.

**هر کلید حاوی داده مستأجر باید `orgId` در کلید داشته باشد.**

## Alternatives Considered

| گزینه                   | مزیت                 | عیب                                    | چرا رد شد                                 |
| ----------------------- | -------------------- | -------------------------------------- | ----------------------------------------- |
| Cache درون‌فرایندی      | ساده‌ترین، سریع‌ترین | میان نمونه‌ها مشترک نیست؛ ابطال ناممکن | Rate Limit و قفل نیازمند حالت مشترک‌اند   |
| Memcached               | سبک، سریع            | بدون ساختار داده غنی؛ بدون ماندگاری    | قفل و Sorted Set لازم است                 |
| Hazelcast یا Ignite     | امکانات بیشتر        | وزن JVM؛ پیچیدگی عملیاتی               | بیش از نیاز                               |
| قفل مبتنی بر PostgreSQL | بدون وابستگی جدید    | فشار روی پایگاه داده اصلی              | Redis برای Cache لازم بود؛ قفل هم همان‌جا |

## Consequences

**مثبت**

- کاهش چشمگیر بار خواندن روی `identity` و `organization`
- Rate Limit دقیق و مشترک میان نمونه‌ها
- قفل توزیع‌شده برای رزرو موجودی و عملیات مالی چندطرفه

**منفی**

- یک نقطه شکست دیگر در MVP (تک‌گره) — ثبت‌شده در Risks S-11
- Cache کهنه اگر ابطال درست کار نکند
- `noeviction` یعنی پر شدن حافظه، نوشتن را رد می‌کند (به‌جای حذف بی‌صدای قفل‌ها)

## Compliance

**هرگز در Redis ذخیره نمی‌شود:**

- موجودی کیف پول — همیشه از پایگاه داده با قفل ردیف
- ورودی یا مانده دفتر کل
- محتوای پیشنهاد مناقصه پیش از مهلت
- هر داده مستأجر بدون `orgId` در کلید

تست قاعده‌محور در CI بررسی می‌کند هیچ کلید Cache بدون پیشوند مستأجر ساخته نمی‌شود.

**دلیل `noeviction`.** Redis اینجا صرفاً Cache نیست؛ قفل و Rate Limit هم در آن است.
حذف خودکار یک قفل زیر فشار حافظه، یک باگ همزمانی تولید می‌کند که ردیابی‌اش تقریباً ناممکن است.
