# ADR-010: Temporal برای Workflow Engine

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26

## Context

فرآیندهای رستا دو ویژگی دارند که آن‌ها را از یک درخواست HTTP جدا می‌کند:

1. **بلندمدت‌اند.** یک مناقصه از انتشار تا انعقاد قرارداد **هفته‌ها** طول می‌کشد.
   پنجره تجمیع تقاضا روزها. چرخه تأیید صورت‌وضعیت روزها.
2. **باید از افت سرویس جان سالم به در ببرند.** اگر `construction-service` در میانه مهلت
   مناقصه Restart شود، **مهلت نباید از دست برود**. برای فرآیندی با اثر حقوقی، این
   غیرقابل مذاکره است.

افزون بر این، تراکنش‌های چندسرویسی (Saga سفارش، تسویه) نیازمند جبران قابل مشاهده و
قابل حسابرسی‌اند.

## Decision

**Temporal 1.26 با SDK TypeScript** برای همه گردش‌کارهای بلندمدت و Sagaها.

چهار Task Queue برای Bulkhead: `rasta-tender` · `rasta-order` · `rasta-settlement` ·
`rasta-scheduled`.

**قاعده مهم:** State Machineها **صریح و جدا از Temporal** تعریف می‌شوند. اگر روزی Temporal
حذف شود، منطق دامنه سالم می‌ماند.

## Alternatives Considered

| گزینه | مزیت | عیب | چرا رد شد |
| --- | --- | --- | --- |
| Cron + جدول وضعیت | بدون وابستگی جدید | هر Timer یک Poll؛ حالت میانی، Retry و جبران همه دست‌ساز | با Restart، مهلت مناقصه از دست می‌رود |
| BPMN Engine (Camunda) | مدل‌سازی گرافیکی، بلوغ | وزن JVM؛ مدل‌سازی گرافیکی برای این تیم ارزش افزوده ندارد | پیچیدگی بدون فایده |
| صف تأخیردار (BullMQ) | سبک، روی Redis موجود | Timer دارد اما حالت، تاریخچه، جبران و Determinism ندارد | برای Saga مالی ناکافی |
| Saga دست‌ساز با رویداد | بدون وابستگی | جبران و Timeout در کد پخش می‌شود؛ مشاهده‌پذیری ضعیف | جبران باید مرکزی و قابل مشاهده باشد |

## Consequences

**مثبت**

- Timer ماندگار — مهلت‌ها با Restart از دست نمی‌روند
- تاریخچه کامل اجرا برای حسابرسی
- Retry و جبران داخلی و استاندارد
- Bulkhead: مناقصه کند، پردازش سفارش را نمی‌خواباند
- Temporal UI مشاهده‌پذیری فوری می‌دهد

**منفی**

- یک سیستم توزیع‌شده کامل با پایگاه داده خودش — وزن عملیاتی بالا
- منحنی یادگیری برای تیم انسانی
- **محدودیت Determinism**: `Date.now()`، `Math.random()` و I/O مستقیم در Workflow ممنوع‌اند
- تغییر کد Workflow نیازمند Versioning دقیق است تا اجراهای جاری نشکنند

## Compliance

- هیچ عارضه بیرونی در کد Workflow — همه در Activity
- هر Activity **Idempotent** با کلید مشتق از `workflowId + activityId`
- قاعده Lint: منع `Date.now()` و `Math.random()` در پوشه `workflows/`
- پیکربندی گردش‌کار (`ApprovalPolicy`، `EvaluationCriteria`) در **شروع** اجرا خوانده و
  در طول عمر آن ثابت نگه داشته می‌شود — هم برای Determinism، هم چون قواعد یک مناقصه
  نباید وسط راه عوض شود
- هر Workflow شکست‌خورده در صف `rasta-settlement` هشدار بحرانی تولید می‌کند
