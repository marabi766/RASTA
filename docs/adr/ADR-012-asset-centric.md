# ADR-012: مدل Asset-Centric و شناسه سراسری دارایی

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26
- **اهمیت:** قاعده بنیادین دامنه

## Context

سند محصول «پرونده الکترونیکی ماشین‌آلات» را «هسته ماژول مدیریت ناوگان» می‌داند و تصریح
می‌کند: «هر رویداد ثبت‌شده در سایر ماژول‌ها به‌صورت خودکار به پرونده دستگاه متصل می‌شود.»

اکثر سیستم‌های سازمانی User-Centric طراحی می‌شوند: کاربر در مرکز، و دارایی یک رکورد
وابسته. در رستا این اشتباه است — دارایی یک عمر ۱۵ تا ۲۵ ساله دارد، میان سازمان‌ها منتقل
می‌شود، و کاربران و مسئولانش بارها عوض می‌شوند.

## Decision

**دارایی، Aggregate Root مرکزی کسب‌وکار است.**

```
Organization → User/Role → Asset → Driver → Usage → Maintenance
                             → Insurance → Orders → Projects → Transactions
```

**شناسه دارایی Organization-Agnostic است.**

- قالب: `AST_<ULID>` — مثلاً `AST_01JBQ8Z4K7M2N5P8R1T3V6X9Y2`
- **هرگز** شامل کد استان، کد سازمان، یا شمارنده محلی
- مالکیت یک **رابطه** (`ownerOrganizationId`) است که تغییر می‌کند؛ **هویت نیست**
- انتقال دارایی: `ASSET_TRANSFERRED` — شناسه و کل تاریخچه با دارایی می‌ماند

همین قاعده برای همه شناسه‌های دامنه‌ای اعمال می‌شود (ORG، USR، ORD، PRJ، …).

## Alternatives Considered

| گزینه | مزیت | عیب | چرا رد شد |
| --- | --- | --- | --- |
| شناسه ترکیبی مثل `YAZD-DEH-0042-EXC-001` | خوانا برای انسان | با انتقال مالکیت بی‌معنا می‌شود؛ استان را Hard-Code می‌کند | مسیر مقیاس ملی را می‌بندد |
| شمارنده صحیح خودافزا | ساده، کوچک | قابل شمارش (BOLA)؛ نیازمند هماهنگی مرکزی | ریسک امنیتی و مقیاس |
| UUIDv4 | استاندارد، غیرقابل حدس | تصادفی → Index پراکنده؛ در Log ناخوانا | ULID همان امنیت را با ترتیب زمانی می‌دهد |
| مدل User-Centric | آشناتر | تاریخچه دارایی با تغییر مسئول گم می‌شود | نقض الزام صریح محصول |

## Consequences

**مثبت**

- دارایی منتقل‌شده کل تاریخچه‌اش را همراه می‌برد
- ULID مرتب‌شدنی است → Index کارآمد، بدون نیاز به هماهنگی مرکزی
- پیشوند در Log خوانا است: `AST_01JBQ8...` بلافاصله می‌گوید چیست
- غیرقابل شمارش → دفاع در برابر BOLA

**منفی**

- شناسه ۳۰ نویسه‌ای برای کاربر نهایی خوانا نیست → نیاز به «شماره پلاک» یا «کد اموال»
  به‌عنوان فیلد جداگانه برای نمایش
- ۲۶ بایت به‌جای ۴ بایت در هر کلید خارجی
- تیم باید عادت کند شناسه را کپی کند، نه بخواند

**خنثی**

- `asset_timeline` یک Read Model است که از رویدادها ساخته می‌شود و باید همیشه قابل
  بازسازی کامل بماند

## Compliance

- `packages/contracts/src/common/identifiers.ts` قالب را تحمیل می‌کند
- بازبینی کد: هیچ شناسه‌ای نباید حاوی نام مکان یا نوع سازمان باشد
- `Asset.ownerOrganizationId` بدون Setter عمومی — فقط با `ASSET_TRANSFERRED`
- `asset_timeline` تست بازسازی دارد: پاک کردن و بازپخش از Offset صفر همان نتیجه را می‌دهد
- تست: انتقال دارایی، تاریخچه را حفظ می‌کند
