# ADR-014: Object Storage سازگار با S3 برای اسناد

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26

## Context

پلتفرم اسناد متعددی نگه می‌دارد: قرارداد، بیمه‌نامه، اسناد مناقصه، صورت‌وضعیت، فاکتور،
مدارک تأمین‌کننده، تصاویر خرابی و گزارش پیشرفت.

سند محصول صریح است که این اسناد **نباید داخل پایگاه داده ذخیره شوند**.

## Decision

**Object Storage سازگار با S3** — MinIO در توسعه، S3 مدیریت‌شده یا MinIO توزیع‌شده در
Production.

`document-service` **فقط فراداده و کنترل دسترسی** را نگه می‌دارد؛ فایل هرگز از پایگاه
داده عبور نمی‌کند و **هرگز از خود سرویس هم عبور نمی‌کند**.

**الگوی آپلود بدون عبور از سرویس:**

```
۱. کلاینت URL امضاشده PUT می‌گیرد (اعتبار ۵ دقیقه)
۲. کلاینت مستقیم به Object Storage آپلود می‌کند
۳. کلاینت فراداده را ثبت می‌کند؛ سرویس وجود شیء را تأیید می‌کند
۴. سرویس DOCUMENT_UPLOADED منتشر می‌کند → اسکن بدافزار ناهمزمان
```

## Alternatives Considered

| گزینه                         | مزیت                 | عیب                                                 | چرا رد شد                    |
| ----------------------------- | -------------------- | --------------------------------------------------- | ---------------------------- |
| ذخیره در PostgreSQL (`bytea`) | تراکنشی، Backup یکجا | پایگاه داده را متورم می‌کند؛ Backup کند؛ حافظه بالا | نقض صریح سند محصول           |
| فایل‌سیستم محلی               | ساده‌ترین            | با چند Replica کار نمی‌کند؛ Backup دشوار            | ناسازگار با Kubernetes       |
| آپلود از راه سرویس            | کنترل کامل           | فایل بزرگ از حافظه و پهنای باند سرویس عبور می‌کند   | Timeout و فشار حافظه بی‌دلیل |
| CDN عمومی                     | سریع برای خواندن     | اسناد محرمانه‌اند؛ دسترسی عمومی مجاز نیست           | ریسک نشت داده                |

## Consequences

**مثبت**

- پایگاه داده سبک می‌ماند؛ Backup سریع
- آپلود فایل بزرگ بار روی سرویس نمی‌گذارد
- URL امضاشده کوتاه‌عمر، دسترسی دقیق می‌دهد
- تعویض MinIO با S3 فقط تغییر پیکربندی است

**منفی**

- **آپلود و ثبت فراداده اتمیک نیستند** — ممکن است شیء یتیم باقی بماند
  (کار پاکسازی دوره‌ای لازم است)
- یک جزء زیرساختی بیشتر
- Backup پایگاه داده و Object Storage باید هماهنگ بازیابی شوند
- در MVP بدون Versioning و بدون Replication

## Compliance

**کنترل‌های امنیتی اجباری:**

- بررسی **Magic Number** برای نوع واقعی محتوا — نه پسوند فایل
- محدودیت اندازه به‌ازای نوع سند
- **کلید شیء از ULID سرور تولید می‌شود**، نه از نام فایل کاربر — دفاع Path Traversal
- Bucket **کاملاً خصوصی**؛ همه دسترسی‌ها با URL امضاشده ۵ دقیقه‌ای
- بررسی مجوزدهی سطح Object پیش از صدور هر URL
- رمزنگاری در حالت سکون
- **فایل هرگز اجرا نمی‌شود و هرگز به‌عنوان HTML سرو نمی‌شود**
- تا اتمام اسکن بدافزار، فایل قابل دانلود نیست

**MVP → PRODUCTION.** اسکن بدافزار در MVP یک Stub است که نتیجه را ثبت می‌کند
(Open Question Q-18). Production: ClamAV یا سرویس معادل.
