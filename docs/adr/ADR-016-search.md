# ADR-016: OpenSearch برای جست‌وجو

- **وضعیت:** Accepted
- **تاریخ:** 2026-08-26

## Context

سند محصول جست‌وجو در پنج حوزه را لازم می‌داند: ماشین‌آلات، تأمین‌کنندگان، کالا و خدمات،
پروژه‌ها و قراردادها. جست‌وجو باید متن آزاد فارسی، فیلتر چندبعدی (Facet) و رتبه‌بندی بر
مبنای امتیاز عملکرد را پشتیبانی کند.

متن فارسی چالش خاصی دارد: تفاوت «ی/ي»، «ک/ك»، نیم‌فاصله، و اشکال مختلف یک واژه.

## Decision

**OpenSearch 2.18** برای جست‌وجو، از **فاز P1**.

در **P0** جست‌وجو با `pg_trgm` در PostgreSQL انجام می‌شود — برای چند هزار دارایی کافی است
و یک وابستگی کمتر در Demo دارد.

پنج Index: `rasta-assets` · `rasta-products` · `rasta-suppliers` · `rasta-tenders` ·
`rasta-contracts`.

## Alternatives Considered

| گزینه | مزیت | عیب | چرا رد شد |
| --- | --- | --- | --- |
| فقط PostgreSQL Full-Text | بدون وابستگی جدید | Facet و رتبه‌بندی پیچیده ضعیف؛ تحلیلگر فارسی محدود | برای مقیاس ملی ناکافی |
| Elasticsearch | بلوغ بالا | تغییر مجوز به SSPL | OpenSearch با مجوز Apache 2.0 |
| Meilisearch یا Typesense | سبک، سریع، ساده | امکانات تجمیع محدودتر | Facet پیچیده لازم است |
| Algolia | مدیریت‌شده، سریع | سرویس بیرونی؛ ملاحظات داده | داده باید تحت کنترل باشد |

## Consequences

**مثبت**

- جست‌وجوی متن آزاد فارسی با تحلیلگر مناسب
- Facet و فیلتر چندبعدی
- رتبه‌بندی بر مبنای امتیاز عملکرد (الزام سند محصول)

**منفی**

- یک جزء زیرساختی سنگین (حداقل ۵۱۲ مگابایت حافظه)
- Index از پایگاه داده می‌تواند واگرا شود
- تأخیر Index (چند ثانیه) — نتیجه جست‌وجو ممکن است کمی کهنه باشد
- در MVP پشت پروفایل Docker Compose است تا لپ‌تاپ‌ها را خفه نکند

## Compliance

**قواعد اجباری:**

- Index **فقط از رویداد** ساخته می‌شود — هرگز خواندن مستقیم پایگاه داده سرویس دیگر
- **هر سند `organizationId` دارد و هر Query یک فیلتر اجباری مستأجر می‌گیرد**
- **OpenSearch هرگز مرجع حقیقت نیست** — همیشه باید کاملاً از Kafka قابل بازسازی باشد
- اسکریپت بازسازی کامل از Offset صفر وجود دارد و در CI تست می‌شود
- تحلیلگر فارسی برای نرمال‌سازی «ی/ي»، «ک/ك» و نیم‌فاصله
