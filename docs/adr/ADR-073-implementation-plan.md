## برش‌ها

### PR 1 — بازپخش بسته به کاربر، بدنه و قاعده‌ی خواندن (`L`، PR #372، ادغام‌شده 2026-10-24)

- Migration برگشت‌پذیر: ستون Nullable `request_hash` روی `usage_record`.
- Hash = SHA-256 روی فراخواننده (کاربر؛ برای فراخوان سرویس، نام سرویس) و بدنه‌ی کانونی (کلیدها مرتب، پیش‌فرض‌ها اعمال‌شده).
- **قاعده‌ی مجوز:** بازپخش رکورد را فقط وقتی برمی‌گرداند که Hash برابر باشد **و** فراخواننده رکورد را با قاعده‌ی `get` بخواند
  (ناظر هر رکورد سازمان؛ دیگران فقط رکورد زیر راننده‌ی خودشان). هر حالت دیگر یک `409 IDEMPOTENCY_KEY_REUSED` یکسان، بی محتوای
  رکورد. همین در بررسی اول، زیر قفل، و در مسیر Unique Violation.
- **قفل سپس بررسی دوباره:** پس از `lockAssetRef` و پیش از بررسی هم‌پوشانی، مرجع دوباره خوانده و با همان قاعده بازپخش می‌شود.
- **ردیف قدیمی بی Hash:** فقط به همان `recordedBy` و فقط با برابری همه‌ی فیلدهای ذخیره‌شده (کمیت‌ها به‌صورت عدد)؛ ردیف ثبت‌شده‌ی
  سرویس هرگز. «مثل امروز» نیست.
- آزمون‌ها: همان/دیگر بدنه، کاربر دیگر، کسی که نمی‌تواند بخواند، **هم‌زمانی در هر دو ترتیب** (زیر قفل و Unique Violation)،
  ردیف قدیمی، مرجع هم‌نام در دو سازمان، OpenAPI؛ `docs/06` § Fleet.
- بیرون از #372: برابری سرآیند `Idempotency-Key` با `clientReference` (`400`) — سخت‌سازی جدا، پیش‌نیاز نیست.

### PR 2a — انتساب با بازه‌ی گزارش‌شده (`M`)

- `resolveOperator`، ناظر بی `driverId`: تخصیص همین `assetId` که `startedAt ≤ periodStart` و (`endedAt` تهی یا
  `periodEnd ≤ endedAt`)؛ دقیقا یکی ← `driverId` و `assignmentId` از آن؛ هیچ یا بیش از یکی ← هر دو `null`.
- ناظر با `driverId`: اعتبارسنجی راننده بی تغییر؛ `assignmentId` = تخصیص پوشاننده‌ی همان راننده و دارایی، وگرنه `null`.
- `SELF`: مجوز بی تغییر؛ `assignmentId` فقط اگر تخصیص فعال بازه را بپوشاند، وگرنه `null`.
- آزمون: ناظر، ماشین از A به B، کارکرد بازه‌ی A ← راننده و تخصیص A (پیش از این PR: B)؛ بازه‌ای که دو تخصیص را بریده ← `null`؛
  `SELF` با تخصیصی که بازه را نپوشانده ← `assignmentId` تهی؛ جداسازی مستاجر. ترتیب کار: نخست آزمونی که امروز B را برمی‌گرداند و
  سرخ است.

### PR 2b — مجوز با تخصیص پوشاننده‌ی بسته‌شده (`S`، پس از Q-150)

- `SELF`: تخصیصی از همین راننده برای همین دارایی که بازه را پوشانده، حتی بسته؛ نبودنش همان `404`.
- آزمون: تخصیص بسته‌شده‌ی پوشاننده ← `201`؛ بازه‌ای که بیرون می‌زند، تخصیص راننده‌ی دیگر، دارایی منتقل‌شده ← `404`.

### PR 3 — `capturedAt` و دیرکرد (`S`)

- میدان اختیاری `capturedAt` (`≤` ساعت سرور + `FUTURE_TOLERANCE_MS`)، ستون Nullable، در نما؛ **نه** در `USAGE_RECORDED`.
- Histogram `fleet_usage_submission_lateness_seconds` با برچسب `origin` (`offline` / `online` / `api`، از پیشوند مرجع) — بی
  `organizationId` (Cardinality، `docs/13`). شاهد Q-149 و Q-153.

### PR 4 — پوسته‌ی PWA (`M`)

- Manifest (`start_url` = `/usage`، `dir: rtl`، `lang: fa`)، آیکون‌ها؛ Service Worker که فقط `/_next/static/*` (Cache-First) و
  پوسته‌ی `/usage` (Network-First با پوسته) را رهگیری می‌کند؛ Cache به نام شناسه‌ی Build؛ پاک کردن Cacheهای قبلی در `activate`؛
  فعال شدن نسخه‌ی تازه فقط بی ارسال در جریان.
- آزمون: هیچ پاسخ API یا HTML دیگری در Cache Storage نمی‌رود (فهرست Cacheها پس از مرور چند صفحه)؛ پوسته آفلاین بالا می‌آید.
- سرآیند CSP و دامنه‌ی Service Worker با `docs/16` § ۱۶٫۱۱ هم‌خوان.

### PR 5 — هسته‌ی صف (`L`)

- IndexedDB با `schemaVersion`؛ قلم: Nonce، مرجع صادرشده (تغییرناپذیر)، مالک (`subject`، `organizationId`)، بدنه‌ی نرمال‌شده،
  `capturedAt`، وضعیت، شمار تلاش، آخرین `correlationId`. هیچ توکن یا شناسه‌ی `sub_`.
- دو Server Action: **صدور مرجع** (نشست ← CSRF اکنون ← مالک ← `off_<kid>_…` با جدیدترین کلید؛ بی اثر جانبی) و **ارسال**
  (نشست ← CSRF اکنون ← مالک و سنجش MAC با `kid` مرجع (`OWNER_MISMATCH`) ← `parseUsageForm` ← `recordUsage` با همان مرجع در
  سرآیند و بدنه). صدور و سنجش با پیاده‌سازی مشترک PR 12؛ حلقه‌ی `OFFLINE_REFERENCE_KEYS` از Secret Store، جدا از
  `WEB_SESSION_SECRET`، و `OFFLINE_REFERENCE_ACTIVE_KID` فقط در پورتال؛ اعتبارسنجی پیکربندی در شروع (حلقه‌ی غایب، خالی یا ناجور،
  یا `ACTIVE_KID` بیرون از حلقه ← شروع نمی‌شود)؛ `kid` ناشناخته ← `NEEDS_CHECK`. چرخش عادی کلیدی را برنمی‌دارد (ADR-073 § ۳ (۲)).

### PR 12 — یک پیاده‌سازی مرجع `off_` (`S`)

- `@rasta/sealing` (رمزنگاری روی `node:crypto`، بی منطق کسب‌وکار): تجزیه‌ی حلقه‌ی `kid:secret` (`kid` یکتا، راز دست‌کم ۳۲ بایت؛
  غایب، خالی یا ناجور ← خطای پیکربندی)، HMAC-SHA256 بریده به ۱۶ بایت روی رشته‌ی JSON ـِ فیلدها، سنجش با زمان ثابت.
- `@rasta/contracts`: دستور `off_<kid>_<nonce>_<mac>`، هدف `rasta/offline-reference/v1`، ترتیب فیلدها
  `[purpose, kid, subject, organizationId, nonce]`؛ تابع صدور و تابع سنجش جدا، تا fleet فقط سنجش را Import کند.
- آزمون: بردار ثابت مشترک که پورتال و fleet هر دو می‌خوانند؛ هر فیلد دیگر (`subject`، سازمان، Nonce، `kid`) ← ناجور؛ `kid`
  ناشناخته ← ناجور؛ مرجع با نویسه‌ی عوض‌شده ← ناجور؛ حلقه‌ی ناجور ← خطا؛ فیلدهای حاوی جداکننده هیچ ترکیب دیگری را نمی‌سازند.
