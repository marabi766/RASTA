## برش‌ها

### PR 1 — بازپخش بسته به بدنه و کاربر (`M`)

- Migration برگشت‌پذیر: ستون Nullable `client_request_hash` روی `usage_record`.
- Hash روی بدنهٔ نرمال‌شده (کمیت‌ها به‌صورت رشته، `source` پس از پیش‌فرض) و `actor`. همان مرجع + همان Hash ← همان نما؛ Hash دیگر
  ← `409 IDEMPOTENCY_KEY_REUSED` بی ردیف و بی رویداد؛ ردیف قدیمی بی Hash ← بازپخش مثل امروز.
- پیش از بازگرداندن هر بازپخش، همان قاعدهٔ `get` (`SELF` فقط رکورد خودش ← وگرنه `404`).
- `Idempotency-Key` اگر بیاید و با `clientReference` برابر نباشد ← `400 VALIDATION_FAILED`.
- آزمون‌ها: همان/دیگر بدنه، کاربر دیگر، رانندهٔ دیگر، هم‌زمانی (مسیر Unique Violation)، مرجع هم‌نام در دو سازمان، OpenAPI.
- `docs/06` § Fleet ردیف Idempotency به‌روز می‌شود.

### PR 2 — تخصیص پوشانندهٔ بازه (`M`)

- `resolveOperator` برای `SELF`: تخصیصی از همین راننده برای همین `assetId` که `startedAt ≤ periodStart` و (`endedAt` تهی یا
  `periodEnd ≤ endedAt`)؛ `assignmentId` همان. نبودنش همان `404` امروز.
- ناظر بی تغییر. آزمون: تخصیص بسته‌شدهٔ پوشاننده ← `201`؛ بازه‌ای که از تخصیص بیرون می‌زند، تخصیص رانندهٔ دیگر، دارایی منتقل‌شده
  ← `404`؛ جداسازی مستأجر.

### PR 3 — `capturedAt` و دیرکرد (`S`)

- میدان اختیاری `capturedAt` (`≤` ساعت سرور + `FUTURE_TOLERANCE_MS`)، ستون Nullable، در نما؛ **نه** در `USAGE_RECORDED`.
- Histogram `fleet_usage_submission_lateness_seconds` با برچسب `origin` (`offline` / `online` / `api`، از پیشوند مرجع) — بی
  `organizationId` (Cardinality، `docs/13`).

### PR 4 — پوستهٔ PWA (`M`)

- Manifest (`start_url` = `/usage`، `dir: rtl`، `lang: fa`)، آیکون‌ها؛ Service Worker که فقط `/_next/static/*` (Cache-First) و
  پوستهٔ `/usage` (Network-First با پوسته) را رهگیری می‌کند؛ Cache به نام شناسهٔ Build؛ پاک کردن Cacheهای قبلی در `activate`؛ فعال
  شدن نسخهٔ تازه فقط بی ارسال در جریان.
- آزمون: هیچ پاسخ API یا HTML دیگری در Cache Storage نمی‌رود (فهرست Cacheها پس از مرور چند صفحه)؛ پوسته آفلاین بالا می‌آید.
- سرآیند CSP و دامنهٔ Service Worker با `docs/16` § ۱۶٫۱۱ هم‌خوان.

### PR 5 — هستهٔ صف (`L`)

- IndexedDB با `schemaVersion`؛ قلم: Nonce، مالک (`subject`، `organizationId`)، بدنه، `capturedAt`، وضعیت، شمار تلاش، آخرین
  `correlationId`. هیچ توکن یا شناسهٔ `sub_`.
- Server Action همگام‌سازی: نشست ← CSRF اکنون ← مالک (`OWNER_MISMATCH`) ← `parseUsageForm` ← مرجع `off_` (هدف
  `rasta-web/offline-reference/v1`) ← `recordUsage` با همان مرجع در سرآیند و بدنه.
- اجراکننده: یکی‌یکی به ترتیب گرفتن؛ پس‌روی ۵ ثانیه تا ۵ دقیقه با Jitter؛ `online` و تمرکز؛ گذار ممنوع رد.
- پرچم `WEB_OFFLINE_USAGE_ENABLED` (پیش‌فرض `false`) تا PR 6.
- آزمون Unit کامل ماشین وضعیت و مرجع (§ ۵ ADR).

### PR 6 — `/usage` روی صف و E2E (`L`)

- فرم با JavaScript همیشه از صف؛ فهرست قلم‌ها با جدول وضعیت ADR-073 § ۳ (۷)؛ ویرایش فقط برای قلم بی‌رکورد؛ حذف با تأیید؛ هشدار
  اختلاف ساعت؛ هشدار خروج/تغییر سازمان با صف پر؛ سقف ۲۰۰ قلم و خطای سهمیه؛ `EXPIRED` با `WEB_OFFLINE_MAX_AGE_HOURS`.
- مجموعهٔ Playwright آفلاین (ADR-073 § ۵) و افزودن سناریو به `docs/14`؛ پرچم در dev/test روشن.
- اگر سناریوی «افزایش دیررس + خواندن دستگاه ناظر» شمارش دوگانه نشان دهد، با `test.fail` و ارجاع به PR 7 ثبت می‌شود.

### PR 7 — ترتیب افزایش و خواندن در maintenance (`S`، مشروط)

- مصرف‌کنندهٔ `USAGE_RECORDED`: افزایشی که `periodEnd`ش از `periodEnd` آخرین خواندن دستگاهِ اعمال‌شده جلوتر نیست، شمارنده را
  جلو نمی‌برد (خواندن دستگاه آن را پیش‌تر شامل شده). آزمون Idempotency و ترتیب‌های جابه‌جا.
