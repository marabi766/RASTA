# ADR-074 implementation plan — Staging روی rasta-dev

- **ADR:** [ADR-074](ADR-074-staging-on-a-single-host.md) · **Backlog:** RUN-002 (سپس RUN-003، RUN-004)
- **وضعیت:** طرح؛ هیچ PR ـِ این فهرست جز S0 شروع نشده است. دور ۲ (2026-10-27): گراف بسته شد، چرخه‌ی O-3 ↔ M-1 شکست، و
  S4، S6، S7، S8، S9 و S10 تقسیم شدند (نگاشت در ADR § «تغییرات r2»).
- **قاعده‌ی اندازه** (`~/pm-board/pre-review-checklist.md`، «Size and stacking»): آن قاعده برای صفحه و فرمان نوشته شده است؛
  اینجا به این معنا خوانده می‌شود: **هر PR یک دغدغه‌ی استقرار، با حداکثر دو فرمان یا Artifact ـِ تازه**. PRی که بیشتر بخواهد،
  پیش از شروع تقسیم می‌شود. ماژول کتابخانه‌ای که فقط همان دو فرمان از آن می‌خوانند جدا شمرده نمی‌شود.
- **وابستگی بیرونی:** کار W#8 828 (ساخت و Scan ـِ تصویر روی Train و `main`) پیش از S3 ادغام شده باشد.

## ترتیب

سه فاز، به این ترتیب و نه جز آن:

1. **فاز ساخت (S1 تا S8b):** هیچ چیز روی میزبان اجرا نمی‌شود جز آزمون‌های یک‌بارمصرف.
2. **فاز M — اندازه‌گیری محدود:** نخستین `up` روی میزبان، فقط در پنجره‌ی انحصاری، زیر قفل و Watchdog، با سقف‌های **موقت
   محافظه‌کارانه** (ADR § ۳، «BLOCKED»): جمع سقف‌ها ≤ `MemTotal − R_host −` Peak ـِ نشست PM. خروجی: عددهای M-1 تا M-3، M-5،
   M-6 (و M-4 فقط اگر گزینه‌ی هم‌زمان خواسته شود). فاز M به O-3 نیاز **ندارد**: پیش‌فرض ADR (پنجره‌ی انحصاری) را اجرا می‌کند.
3. **تأیید O-3، سپس استقرار عادی (S8m، S8c به بعد).** O-3 روی عددهای فاز M تصمیم می‌گیرد؛ هیچ استقرار عادی پیش از آن نیست.

```
فاز ساخت:  S0 → { S1, S1b, S2a → S2b → S3, S4a → { S4b, S5b, S6a, S6b }, S5a, S7a, S7b } → S8a → S8b
فاز M:     S8b → [اندازه‌گیری] → S8m
استقرار:   S8m + O-3 → S8c → S9a؛  S8b → S8d؛  { S9a، S8d } → S9b → S9c → S10b؛  { S8c، S8d } → S10a
پذیرش:     { S9b، S9c، S10a، S10b، O-1، O-6 } → RUN-002
```

جدول «پیش‌نیاز» پایین منبع است و نمودار فقط خلاصه‌ی آن. **S1 و S1b پیش‌نیاز S8a اند**، پس هیچ `up` ـِ Staging — حتی در فاز M —
بی پیکربندی هم‌شکل Production و Listener ـِ مقید اجرا نمی‌شود.

## وارسی گراف (r2)

پیش از هر بازنگری این برنامه، جدول بالا با این قاعده‌ها وارسی می‌شود (دور ۲: اسکریپت خصوصی روی همین جدول، نتیجه در STATUS):

1. **بی چرخه:** ترتیب توپولوژیک وجود دارد.
2. **بسته:** هر گره جز S0 دست‌کم یک پیش‌نیاز دارد، و هر گره به «پذیرش RUN-002» می‌رسد (هیچ PR ـِ آویزان، مثل S1 ـِ دور ۱).
3. **پیش‌نیاز امنیتی پیش از اجرا:** هر PR که روی میزبان چیزی اجرا می‌کند (S8a به بعد و فاز M) به‌طور تراگذر به S1، S1b، S4b،
   S5b، S7a و S7b وابسته است.
4. **تصمیم مالک پیش از مصرف:** هر O-n پیش از نخستین PR ـِ مصرف‌کننده‌اش است، و هیچ O-n به عددی وابسته نیست که فقط پس از
   خودش اندازه گرفته می‌شود (چرخه‌ی دور ۱: O-3 پیش از S8، M-1 درون S8).

## آنچه این برنامه شامل نیست

- Kubernetes، Helm و Production (همچنان `docs/12`).
- اندازه‌گیری بار، Alert و Restore ـِ واقعی با تراز دفتر کل در مقیاس، و فرمان Restore (RUN-003).
- هر داده‌ی واقعی یا کاربر Pilot (RUN-004؛ ADR § ۲).
- سقف حافظه برای Workerها یا Stack ـِ توسعه (تصمیم PM؛ ADR § ۳ بند ۳ فقط شرط گزینه‌ی هم‌زمان را می‌گوید).
- برآورد امتیاز: RUN-002 همان ۲۱ امتیاز Backlog را دارد؛ این برنامه عددی برایش جعل نمی‌کند.
