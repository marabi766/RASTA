# راه‌اندازی نسخهٔ Investor Preview روی یک ماشین دیگر

> شاخه: `demo/investor-preview` — نسخهٔ پیش‌نمایش سرمایه‌گذار.
> این شاخه عمداً جدا نگه داشته می‌شود و به `main` merge نمی‌شود.

این سند برای کسی نوشته شده که مخزن را روی یک ماشین ویندوزی تازه clone می‌کند و
باید نمایش را اجرا کند. هر دستور، اجراشده و تأییدشده است مگر جایی که صریحاً
خلافش گفته شده باشد.

---

## ۰. سه سطح اجرا — کدام را لازم دارید؟

| سطح                | چه چیزی کار می‌کند                                                                                                      | چه چیزی لازم است           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| **۰ — ارائه**      | همهٔ صفحه‌ها، با دادهٔ **ساختگیِ برچسب‌خورده**؛ بدون هیچ Backend                                                        | فقط Node + pnpm            |
| **الف — فقط رابط** | روایت هدایت‌شده، داشبورد، نقشهٔ قابلیت‌ها، همهٔ صفحه‌های ساخته‌نشده، و **ورود واقعی Keycloak**                          | Node + pnpm + Keycloak     |
| **ب — نمایش کامل** | همهٔ موارد بالا، به‌علاوهٔ صفحه‌های LIVE با دادهٔ واقعی: دارایی، ناوگان، نگهداری، بازار، سفارش، کیف پول، دفتر کل، اسناد | تمام Stack + مهاجرت و Seed |

**سطح ۰ در این سند نیست** — راهنمای جداگانه‌اش
[`presentation-mode.md`](presentation-mode.md) است. اگر Docker در دسترس ندارید
یا فقط می‌خواهید محصول را روی یک لپ‌تاپ نشان دهید، همان را بخوانید؛ یک دستور
است و هیچ زیرساختی نمی‌خواهد.

اگر فقط پانزده دقیقه وقت دارید و Keycloak در دسترس است، **سطح الف کافی
است**. صفحه‌های LIVE در آن حالت به‌جای داده، وضعیت «سرویس در دسترس نیست» را
صادقانه نشان می‌دهند و هیچ‌چیز نمی‌شکند.

## ۳. پیکربندی

```bash
cp .env.example .env
```

`.env` در `.gitignore` است و **هرگز Commit نمی‌شود**. مقادیر داخل
`.env.example` مقادیر توسعهٔ یک‌بارمصرف‌اند، نه راز واقعی؛ برای هر استقرار
واقعی باید عوض شوند.

چهار متغیری که رابط کاربری می‌خواند، همگی عمومی‌اند:

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:3000
NEXT_PUBLIC_KEYCLOAK_URL=http://localhost:8080
NEXT_PUBLIC_KEYCLOAK_REALM=rasta
NEXT_PUBLIC_KEYCLOAK_CLIENT_ID=rasta-web
```

`apps/web/next.config.mjs` همین فایل ریشه را می‌خواند و **فقط کلیدهای
`NEXT_PUBLIC_`** را برمی‌دارد؛ هیچ Secret دیگری از آن فایل به Bundle مرورگر
راه ندارد.

> ⚠️ **اگر پورت ۳۰۰۰ روی ماشین شما اشغال است** (که طبق `PROJECT_MEMORY.md` § ۷
> روی ماشین توسعهٔ اصلی همین‌طور است)، هم `PORT_API_GATEWAY` و هم
> `NEXT_PUBLIC_API_BASE_URL` را با هم به یک پورت آزاد — مثلاً ۳۰۱۰ — تغییر
> دهید. اگر فقط یکی را عوض کنید، صفحه‌های LIVE خطای «ارتباط برقرار نشد»
> می‌دهند.
>
> `GATEWAY_CORS_ORIGINS` باید `http://localhost:3200` را داشته باشد؛ در
> `.env.example` از پیش دارد.

## ۵. سطح الف — فقط رابط کاربری

فقط Keycloak لازم است:

```bash
docker compose up -d keycloak
```

Realm از `infrastructure/docker/keycloak/rasta-realm.json` وارد می‌شود. تا وقتی
این آدرس `200` بدهد صبر کنید:

```bash
curl -s -o NUL -w "%{http_code}\n" http://localhost:8080/realms/rasta/.well-known/openid-configuration
```

سپس پورتال:

```bash
pnpm --filter @rasta/web dev
```

`http://localhost:3200` را باز کنید. تمام.

## ۶. سطح ب — نمایش کامل

### ۶٫۱ بالا آوردن زیرساخت

```bash
pnpm infra:up
```

PostgreSQL، Redis، Kafka، Keycloak، MinIO و Temporal را بالا می‌آورد. منتظر
سالم شدن بمانید:

```bash
docker compose ps
```

ستون وضعیت باید برای PostgreSQL، Redis، Kafka، Keycloak و MinIO مقدار
`healthy` نشان دهد. Kafka معمولاً دیرتر از بقیه آماده می‌شود.

### ۶٫۲ تولید Client، مهاجرت و Seed — به همین ترتیب

ترتیب مهم است: تولید Client پیش از مهاجرت، و مهاجرت پیش از Seed.

```bash
pnpm db:generate
```

```bash
pnpm db:migrate
```

```bash
pnpm db:seed
```

> `db:seed` روی سرویس‌هایی اجرا می‌شود که Seed دارند: identity، organization،
> asset، fleet، maintenance، economic و marketplace. `document-service` و
> `supplier-service` اسکریپت Seed ندارند و این خطا نیست.

### ۶٫۳ اجرای سرویس‌ها و پورتال

```bash
pnpm dev
```

همهٔ سرویس‌های پیاده‌شده به‌علاوهٔ `apps/web` را با هم بالا می‌آورد.

اگر ترجیح می‌دهید فقط آنچه نمایش لازم دارد بالا بیاید، این‌ها کافی‌اند —
درگاه، هویت، سازمان، دارایی، ناوگان، نگهداری، بازار، تأمین‌کننده، اقتصادی،
اسناد و پورتال:

```bash
pnpm --filter @rasta/api-gateway --filter @rasta/identity-service --filter @rasta/organization-service --filter @rasta/asset-service --filter @rasta/fleet-service --filter @rasta/maintenance-service --filter @rasta/marketplace-service --filter @rasta/supplier-service --filter @rasta/economic-service --filter @rasta/document-service --filter @rasta/web --parallel dev
```

## ۷. بررسی آمادگی پیش از ارائه

```bash
node scripts/demo-preflight.mjs
```

اسکریپت **فقط می‌خواند**: اتصال TCP باز می‌کند، مسیر سلامت را `GET` می‌زند و
فایل می‌خواند. هیچ سرویسی را بالا نمی‌آورد، هیچ پایگاه داده‌ای را Reset یا Seed
نمی‌کند و هیچ فرایندی را نمی‌کشد. این محدودیت عمدی است: اسکریپتی که بی‌سروصدا
مشکل را «درست» کند، دقیقاً همان ابزاری است که پنج دقیقه پیش از ارائه نباید
داشته باشید — تنها زمانی که به وضعیت واقعی نیاز دارید، همان زمانی است که یک
اسکریپت خودترمیم آن را پنهان می‌کند.

خروجی، دو سطح را جدا گزارش می‌کند و برای هر مورد ناموفق، دقیقاً دستوری را که
باید اجرا کنید چاپ می‌کند. خروج با کد `0` یعنی سطح ب کامل آماده است.

این اسکریپت به سطح ۰ (حالت ارائه) ربطی ندارد و در آنجا به‌درستی شکست می‌خورد:
آن حالت هیچ درگاه و هیچ Keycloak ای ندارد که سنجیده شود.

برای استفاده در اسکریپت:

```bash
node scripts/demo-preflight.mjs --json
```

## ۹. کاربران نمایش

کاربران Seed در `infrastructure/docker/keycloak/rasta-realm.json` تعریف شده‌اند
و رمزهایشان در همان فایل است. **رمزها در این سند نقل نمی‌شوند** و نباید در
هیچ سند دیگری نقل شوند؛ فایل Realm، منبع یگانهٔ آن‌هاست.

| نام کاربری         | نقش‌ها                                              | سازمان فعال         |
| ------------------ | --------------------------------------------------- | ------------------- |
| `dehyari.admin`    | ORGANIZATION_ADMIN، FLEET_MANAGER، PROCUREMENT_USER | `ORG-DEH-0001`      |
| `dehyari.admin.b`  | ORGANIZATION_ADMIN                                  | `ORG-DEH-0002`      |
| `union.admin`      | UNION_ADMIN                                         | `ORG-UNION-YAZD`    |
| `system.admin`     | SYSTEM_ADMIN                                        | `ORG-UNION-YAZD`    |
| `province.auditor` | AUDITOR                                             | `ORG-PROVINCE-YAZD` |

**برای نمایش، `dehyari.admin` را استفاده کنید** — تنها کاربری که هر سه نقش
لازم برای ناوگان، بازار و مالی را با هم دارد.

`province.auditor` برای نشان دادن یک نکتهٔ امنیتی مفید است: این نقش روی هر
مسیر مالی `403` می‌گیرد و پورتال آن را به‌عنوان «رد شدن»، نه «خطا»، نمایش
می‌دهد.

> **نکتهٔ عملیاتی.** کاربران Seed فقط `active_organization_id` دارند و
> `organization_ids` ندارند. یعنی ادعای `org_ids` روی توکن خالی می‌آید و
> مجموعهٔ عضویت به همان یک سازمان تقلیل می‌یابد؛ انتخابگر سازمان یک گزینه نشان
> می‌دهد و همان را خودکار انتخاب می‌کند. برای نمایش سناریوی چندسازمانی،
> `organization_ids` باید در همگام‌سازی Keycloak پر شود — کار سرویس هویت، نه
> رابط کاربری.

## ۱۰. خاموش کردن

بدون حذف داده — حالت پیش‌فرض و همانی که تقریباً همیشه می‌خواهید:

```bash
pnpm infra:down
```

Volumeها دست‌نخورده می‌مانند، بنابراین دفعهٔ بعد Seed لازم نیست.

### ♦ Reset کامل — مخرب

> ⚠️ **هشدار: دستور زیر همهٔ Volumeها را حذف می‌کند.** هر پایگاه داده، هر فایل
> در MinIO و هر Topic کافکا از بین می‌رود و باید دوباره مهاجرت و Seed کنید.
> **اگر کس دیگری هم‌زمان از همین Stack استفاده می‌کند، این دستور کار او را هم
> از بین می‌برد.** پیش از اجرا بپرسید.

```bash
pnpm infra:reset
```

سپس مرحلهٔ ۶٫۲ را دوباره اجرا کنید.

## ۱۱. عیب‌یابی — مواردی که واقعاً روی ویندوز پیش می‌آیند

### پورت اشغال است، اما هیچ برنامه‌ای در حال اجرا نیست

ویندوز بازه‌هایی از پورت را برای Hyper-V و WSL رزرو می‌کند و اتصال به آن‌ها
بدون هیچ فرایند قابل مشاهده‌ای رد می‌شود.

```bash
netsh interface ipv4 show excludedportrange protocol=tcp
```

اگر پورت شما داخل یکی از بازه‌هاست، **پورت را عوض کنید**؛ آزاد کردن آن بازه
تنظیمات شبکهٔ ماشین را تغییر می‌دهد و ارزشش را ندارد. مقدار متناظر در `.env` را
هم به‌روز کنید.

برای دیدن اینکه چه چیزی یک پورت را گرفته:

```bash
netstat -ano | findstr :3000
```

### درگاه بالاست ولی پورتال «ارتباط برقرار نشد» می‌دهد

`NEXT_PUBLIC_API_BASE_URL` با `PORT_API_GATEWAY` یکی نیست. هر دو باید یک پورت
باشند. پس از تغییر `.env`، پورتال را دوباره اجرا کنید — Next مقادیر
`NEXT_PUBLIC_` را در زمان Build جاسازی می‌کند.

### پورتال `500` می‌دهد

معمولاً وقتی رخ می‌دهد که `next build` روی همان `.next` اجرا شده که `next dev`
دارد از آن سرو می‌کند:

```bash
rm -rf apps/web/.next
```

سپس دوباره `pnpm --filter @rasta/web dev`.

### ورود کار می‌کند اما پس از Reload دوباره خارج می‌شوید

رفتار شناخته‌شده و مستند. Keycloak به‌صورت پیش‌فرض `frame-ancestors 'self'` را
اعمال می‌کند و اجازه نمی‌دهد در iframe سایت دیگری رندر شود، بنابراین بازیابی
خودکار نشست (Silent Renew) مسدود می‌شود. ورود تعاملی یک Redirect تمام‌صفحه است
و اصلاً تأثیر نمی‌گیرد. جزئیات و دلیل اینکه در این شاخه رفع نشده، در
`apps/web/src/lib/auth/user-manager.ts` نوشته شده است.

**در ارائه، پس از ورود صفحه را Reload نکنید.**

### Keycloak بالا می‌آید ولی Realm پیدا نمی‌شود

Import در نخستین اجرا انجام می‌شود. اگر Volume از قبل وجود داشته و خراب باشد:

```bash
docker compose logs keycloak --tail 100
```

### Kafka دیر آماده می‌شود یا سرویس‌ها هنگام Start شکست می‌خورند

Kafka در حالت KRaft چند ثانیه بیشتر از بقیه طول می‌کشد. سرویس‌ها را پس از
`healthy` شدن آن اجرا کنید:

```bash
docker compose ps kafka
```

### `db:migrate` می‌گوید متغیر تنظیم نشده است

Turbo در محیط سخت‌گیرانه اجرا می‌شود و متغیری را که به آن معرفی نشده رد
می‌کند. مطمئن شوید `.env` در **ریشهٔ** مخزن است، نه داخل پوشهٔ سرویس.

### Temporal بالا نمی‌آید

هیچ سرویسی هنوز از Temporal استفاده نمی‌کند مگر جریان سفارش. برای سطح الف و
برای بیشتر سطح ب، می‌توانید بدون آن ادامه دهید.

## ۱۲. آنچه این نسخه انجام **نمی‌دهد**

- هیچ نوشتنی روی هیچ سرویسی: نه ثبت سفارش، نه تأیید تعمیر، نه ساخت کاربر، نه
  آپلود سند. همهٔ صفحه‌ها فقط می‌خوانند و هرکدام همین را روی خودشان می‌گویند.
- هیچ اتصال بانکی. پرداخت پشت `MockPaymentProvider` شبیه‌سازی می‌شود و صفحهٔ
  کیف پول این را از خود API می‌پرسد، نه از یک متن ثابت.
- هیچ شاخص عملیاتی ساختگی. سرویس تحلیلی ساخته نشده، بنابراین داشبورد فقط
  وضعیت ساخت را گزارش می‌کند.
