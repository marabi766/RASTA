# امنیت

> معماری کامل، Threat Model و کنترل‌ها در
> [`../09-security-architecture.md`](../09-security-architecture.md).

**این سند از عبارت‌هایی مانند «Military Grade Security» یا «۱۰۰٪ امن» استفاده نمی‌کند.**
امنیت با کنترل‌های مشخص و **قابل تست** توصیف می‌شود، نه با صفت.

---

## اصول

```
۱. هر Endpoint پیش‌فرض بسته است
۲. مجوزدهی در سطح Object، نه فقط سطح Endpoint
۳. Zero Trust — هیچ اعتماد ضمنی به شبکه داخلی
۴. هیچ Feature‌ای «برای Demo» از Auth، اعتبارسنجی یا Audit عبور نمی‌کند
۵. هر تغییر وضعیت، رکورد Audit تولید می‌کند
```

## مدیریت Secret

| محیط | مکانیزم |
| --- | --- |
| Local | `.env` (در `.gitignore`) — فقط مقادیر یک‌بارمصرف |
| CI | GitHub Actions Secrets |
| Staging / Production | Kubernetes Secret از External Secrets Operator |

```
🚫 هیچ Secret واقعی در Repository — هرگز، حتی موقت
🚫 هیچ Secret در Log، پیام خطا یا Payload رویداد
🚫 هیچ Secret در پیام Commit یا نام Branch
✅ فقط .env.example با مقادیر آشکارا ساختگی
✅ چرخش کلید بدون تغییر کد (تزریق از محیط)
✅ اسکن Secret در CI روی هر Push
```

**اگر Secret نشت کرد:** اولین گام همیشه **چرخش** است، نه پاک کردن تاریخچه Git.
تاریخچه ممکن است قبلاً Clone شده باشد.

## اسکن‌های امنیتی در CI

| مرحله | ابزار | سیاست شکست |
| --- | --- | --- |
| اسکن Secret | Gitleaks | **هر یافته = شکست** |
| اسکن وابستگی | `pnpm audit` + OSV Scanner | Critical/High = شکست |
| SAST | Semgrep + ESLint security | High = شکست |
| اسکن Container | Trivy | Critical = شکست |
| اسکن IaC | Trivy config | High = شکست |
| **تست مجوزدهی** | Jest | **هر شکست = شکست** |
| **تست Tenant Isolation** | Jest | **هر شکست = شکست** |
| DAST | OWASP ZAP Baseline (شبانه) | High = هشدار |

```bash
pnpm audit --audit-level=high
pnpm security:scan          # اجرای همه اسکن‌ها به‌صورت محلی
```

## تست‌های امنیتی اجباری

هر Feature که داده مستأجر را لمس می‌کند:

```bash
pnpm --filter @rasta/<service> test -- --testNamePattern="tenant isolation"
pnpm --filter @rasta/<service> test -- --testNamePattern="authorization"
```

**تست جداسازی که شکست می‌خورد، یک نشتی داده است — نه یک تست شکننده.**

## Checklist امنیت هر Feature

- [ ] احراز هویت الزامی (یا `@Public()` صریح و مستند)
- [ ] بررسی نقش
- [ ] **بررسی سطح Object (BOLA)**
- [ ] هر Query دارای `organizationId`
- [ ] **تست Tenant Isolation نوشته و سبز**
- [ ] ورودی با Zod `.strict()`
- [ ] `AuditEvent` برای تغییر وضعیت
- [ ] `Idempotency-Key` برای عمل مالی یا برگشت‌ناپذیر
- [ ] پیام خطا داده حساس فاش نمی‌کند
- [ ] هیچ داده حساسی در Log یا Payload رویداد
- [ ] هیچ Secret جدیدی در کد

## قاعده `404` به‌جای `403`

منبع متعلق به مستأجر دیگر **`404 NOT_FOUND`** برمی‌گرداند، نه `403`.

**چرا؟** `403` وجود منبع را تأیید می‌کند. مهاجم می‌تواند با شمارش شناسه‌ها بفهمد چه
دارایی‌هایی در سازمان‌های دیگر وجود دارد. `404` این نشتی را می‌بندد.

## گزارش آسیب‌پذیری

آسیب‌پذیری امنیتی را **در Issue عمومی گزارش نکنید**. مسیر گزارش خصوصی را با تیم پلتفرم
هماهنگ کنید.

## طبقه‌بندی داده

| طبقه | نمونه | کنترل |
| --- | --- | --- |
| عمومی | فهرست کالا، مناقصه منتشرشده | بدون محدودیت |
| داخلی | مشخصات دارایی، سوابق تعمیر | محدود به مستأجر |
| محرمانه | قیمت پیشنهادی، صورت‌وضعیت، موجودی کیف پول | محدود به طرفین؛ در Log ظاهر نمی‌شود |
| حساس شخصی | کد ملی، شماره تماس، مدارک هویتی | رمزنگاری در حالت سکون؛ دسترسی با Audit |
| **بحرانی** | **پیشنهاد مناقصه پیش از مهلت** | **رمزنگاری؛ غیرقابل مشاهده حتی برای اپراتور** |
